# EventBridge → AWS Batch

The `targets` connection submits a generated EC2 Batch job definition to a job queue on the connected Batch node. Select a `Batch Job Definition` node by name in `job_definition_name`; `job_name` defaults to `eventbridge-job`. Optional `array_size` and `job_attempts` map to native Batch target parameters. `target_id` distinguishes multiple targets on one rule. A Batch node with no queue name gets a deterministic `<node-name>-queue` when this connection is present; the queue is backed by that node's compute environment.

The supported compute environment type for this connection is `UNMANAGED`, with a configured Batch service role. Register and maintain EC2 capacity for that environment outside this connection before expecting jobs to run. The generated job definition uses EC2 container properties. Managed compute environments require additional compute-resource configuration that this generator does not yet provide.

The EventBridge rule module owns the target and a dedicated role trusted by `events.amazonaws.com` for the rule. Its policy grants only `batch:SubmitJob` on the generated queue ARN and selected revision-qualified job-definition ARN. Those ARNs reach the rule through module inputs; the queue and job definition remain in their own modules. The connection does not configure container overrides, job parameters, retry policies, dead-letter queues, or monitoring. See the [Batch EventBridge role](https://docs.aws.amazon.com/batch/latest/userguide/CWE_IAM_role.html) and [Terraform Batch target arguments](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/cloudwatch_event_target#batch_target).
