# Route 53 ACM DNS validation

Route 53 → Certificate Manager (`validates_certificate`) creates public certificate validation CNAMEs and waits for issuance. The typed connection exposes `ttl` (default 60 seconds, range 1–2147483647). Public DNS validation is required; email validation, private hosted zones, VPC-associated zones, and Private CA certificates are rejected.

Connect every hosted zone needed by the certificate's primary name and SANs. Each name selects the most specific connected zone whose DNS suffix matches. Uncovered names and competing equally specific hosted zones are rejected. Zone names may use a trailing dot; matching is case insensitive. Wildcard and apex names share one validation record. Certificates sharing a validation name, including certificates in different Regions, must agree on one zone and TTL; the lexicographically first certificate supplies its native validation option. Identical repeated connectors contribute no additional resources.

The Route 53 module owns one `aws_route53_record` resource with a static map of canonical validation-domain keys. Record values come from the owning certificate's native `domain_validation_options` output through a typed module input. Keeping keys independent of computed CNAME tokens permits the first Terraform plan before certificates exist. Existing CNAMEs must be imported into these addresses; the generator does not enable `allow_overwrite`.

Each certificate module receives its selected record FQDNs and owns one `aws_acm_certificate_validation` waiter in `certificate_issuance.tf`. API Gateway and Client VPN share this same waiter. For DNS-connected certificates, both `certificate_arn` and `issued_certificate_arn` expose its ready ARN, so existing Load Balancer and CloudFront consumers wait too. Native validation options stay independent of issuance. This separation lets a hosted zone also alias a secured Load Balancer or CloudFront distribution without a dependency cycle. No execution roles or workload IAM grants are created.

Terraform preconditions require DNS validation, the generated canonical certificate-name set, a public native hosted zone, and its generated zone name. Regenerate the project when changing certificate validation names or hosted-zone names; these determine record ownership and plan keys. Changing between an apex name and its wildcard or repeating SANs preserves the same canonical validation name.

Delegate public hosted zones to their exported name servers before certificate consumers can complete. Parent/child delegation, domain registration, DNS propagation, and CAA restrictions remain operational prerequisites. The preview reports managed records/waiters and delegation guidance. It suppresses the manual DNS/email-validation warning on API Gateway and Client VPN consumers when managed DNS validation exists.

The implementation follows [AWS ACM DNS validation](https://docs.aws.amazon.com/acm/latest/userguide/dns-validation.html), the [Terraform issuance waiter](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/acm_certificate_validation), and the [Route 53 record schema](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/route53_record).
