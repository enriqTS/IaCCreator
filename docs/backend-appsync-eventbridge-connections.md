# AppSync → EventBridge

The `resolves_with` connection attaches an AppSync JavaScript unit resolver to a selected GraphQL field. Configure `field_name`, `event_source`, and `detail_type`. The GraphQL `type_name` defaults to `Mutation`, and `detail_argument` defaults to `input`. The API node must provide a schema with that field and an input object argument. The field should return `ID` or `String`: a successful call returns the published event's `EventId`. The source cannot use the reserved `aws.` prefix.

Each resolver publishes exactly one event containing the configured source and detail type plus the GraphQL input object as `detail`. Its response raises a GraphQL error for a data-source error, a failed entry, or a missing Event ID. EventBridge may accept publication without matching any rule or delivering to a target. Configure the target EventBridge rule's `event_pattern` to match the chosen `source` and `detail-type`, and add target connections separately. The same connection works with the generated custom bus or with the existing default bus lookup.

One API-owned EventBridge data source and role serve all connected fields targeting the same EventBridge node. The role trusts AppSync only for the generated API ARN and grants `events:PutEvents` only on that node's bus ARN. The ARN crosses into the API module as a Terraform input, and data-source creation waits for its role policy. A GraphQL field can have only one generated resolver, including across Lambda, DynamoDB, and OpenSearch connections.

The request and response follow the [AppSync EventBridge JavaScript reference](https://docs.aws.amazon.com/appsync/latest/devguide/resolver-reference-eventbridge-js.html). The generated data source uses the provider's [`event_bridge_config` block](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/appsync_datasource); the event fields follow the [EventBridge PutEvents API](https://docs.aws.amazon.com/eventbridge/latest/APIReference/API_PutEventsRequestEntry.html).
