# EventBridge → ECS

The `targets` connection launches the generated ECS task definition in its cluster for each matching rule event. The target uses Fargate with the ECS workload's configured subnet IDs, security groups, and public-IP setting. Connect at least one managed Subnet or provide external subnet IDs on the ECS node. `task_count` defaults to one and accepts 1–10; `target_id` distinguishes multiple targets on the same rule. ECS configurations that request a different launch type are rejected.

The EventBridge rule module owns the target and an invocation role trusted by `events.amazonaws.com` for that rule. Its inline policy grants `ecs:RunTask` on the selected task-definition revision, conditioned on the connected cluster, and `iam:PassRole` on the ECS task role only when passed to `ecs-tasks.amazonaws.com`. Cluster ARN, task-definition ARN, task-role ARN, and effective network values travel from the ECS module through typed module inputs. The connection does not change the ECS service's desired count.

Each event can start one or more tasks. This connection does not configure container overrides or inject the matched event into container environment variables; configure application input and idempotency separately. EventBridge retries and dead-letter handling, application monitoring, VPC egress, and container image access remain separate configuration. See [EventBridge target roles](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-events-iam-roles.html) and the [Terraform ECS target schema](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/cloudwatch_event_target#ecs_target).
