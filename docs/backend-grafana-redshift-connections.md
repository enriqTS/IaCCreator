# Managed Grafana Redshift connections

Managed Grafana → Redshift (`queries`) requires an existing `database_name` and `database_user`. The backend exposes both selectors through `/api/connection-schemas`. This connection accepts lowercase ASCII names beginning with a letter, followed by letters, digits, or underscores, up to 64 characters. It rejects `public` and the cluster's configured administrator username. Create the database and user separately and give the user appropriate read-only SQL grants; IAM cannot verify whether another selected user has superuser privileges or restrict SQL text to `SELECT`. See [temporary database credentials](https://docs.aws.amazon.com/redshift/latest/APIReference/API_GetClusterCredentials.html).

Connected provisioned clusters require explicit `node_type` and `master_username`. Optional `number_of_nodes` controls capacity; when omitted, the provider uses one node. Choose a node type and count supported in the deployment Region. Connections set `manage_master_password = true`, allowing Redshift to manage its administrator password through Secrets Manager. The deployment identity needs the corresponding service permissions. The generated Grafana role has no administrator-secret read permission, and no password value is generated or exported. Unconnected clusters retain their existing password behavior. See the [AWS provider resource](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/redshift_cluster).

`GrafanaRedshiftSource` joins the shared workspace-owned customer-managed role alongside Prometheus, CloudWatch Logs, Timestream, OpenSearch, and Athena. Each cluster exports its native ARN, identifier, ARN-derived Region, and administrator username. The typed `redshift_databases` input carries these identities and the selected database/user pairs into Grafana. Terraform preconditions reject mismatched account, partition, identifier, or Region, unsafe selectors, and administrator bindings, including username overrides made after generation. Targets depend only on their own native resources, keeping the dependency graph acyclic. Same-account cross-Region queries are supported; organization and cross-account role chaining are excluded.

Execution and metadata permissions name only connected cluster ARNs: `redshift-data:ExecuteStatement`, `DescribeTable`, `ListDatabases`, `ListSchemas`, and `ListTables`. Metadata discovery can reveal other database/schema/table names according to database permissions. Each selected pair receives its own `redshift:GetClusterCredentials` statement naming the exact `dbuser` and `dbname` ARNs and requiring both `redshift:DbUser` and `redshift:DbName`. Separate statements prevent combining a selected user with another selected database, and requiring `DbName` prevents omitted-database requests from broadening login scope. No user creation, group joining, cluster mutation, IAM-derived user credentials, or Serverless credentials are granted. See the [Redshift authorization reference](https://docs.aws.amazon.com/service-authorization/latest/reference/list_redshift.html) and [Data API resource scopes](https://docs.aws.amazon.com/service-authorization/latest/reference/list_redshift-data.html).

`DescribeStatement`, `GetStatementResult`, `CancelStatement`, and `ListStatements` require wildcard resources, restricted to connected Regions by `aws:RequestedRegion`. The Data API's default statement ownership shares access among sessions of the same workspace role, including across Grafana users. There is no per-user isolation or per-cluster result restriction for these APIs. The policy preserves that role-wide ownership so refreshed Grafana role sessions can retrieve asynchronous results; it does not impose an individual-session owner condition. Other identity grants can broaden access, and service policies can deny it. See [Data API ownership rules](https://docs.aws.amazon.com/redshift/latest/mgmt/data-api-iam.html).

The Grafana module exports `redshift_data_sources`, keyed by `<cluster-node-name>:<database-name>:<database-user>`. Each payload uses `grafana-redshift-datasource`, proxy access, default AWS role credentials, and the native cluster identifier/Region. `database` and `dbUser` retain the selected values. `useServerless`, `useManagedSecret`, and `withEvent` are false. UIDs hash the native cluster ARN, database, and user, preserving identity across diagram node renames. Display names are capped at 190 characters with a binding-specific hash; output keys and selectors remain complete. No password, access key, token, or custom endpoint is exported. See [Redshift plugin configuration](https://grafana.com/docs/plugins/grafana-redshift-datasource/latest/configure/) and its [Data API implementation](https://github.com/grafana/redshift-datasource/blob/main/pkg/redshift/api/api.go).

Install a plugin compatible with the workspace's Grafana version and apply the exported JSON using an authorized Grafana identity. For workspace `grafana`, cluster node `warehouse`, database `application`, and user `grafana_reader`, run from the generated environment directory:

```sh
terraform output -json grafana > grafana-outputs.json
jq '.redshift_data_sources["warehouse:application:grafana_reader"]' grafana-outputs.json > redshift-data-source.json
```

Submit the payload to `POST https://<workspace_endpoint>/api/datasources`, or update with `PUT /api/datasources/uid/<uid>`. Use Save & test, which executes `SELECT 1`, then query an authorized table. Cluster dropdown discovery via `DescribeClusters` is not granted; use the exported native settings. Database grants, dashboards, users, and data lifecycle remain operational tasks.

Use a Data API eligible provisioned node type and VPC placement. Grafana communicates with AWS APIs rather than the SQL endpoint; private workspace egress, endpoint policies, encryption grants, deployment prerequisites, and service availability remain separately configured. Redshift Serverless, secret-based data-source authentication, IAM Identity Center trusted identity propagation, and database-user provisioning are unmodeled. See [Data API prerequisites](https://docs.aws.amazon.com/redshift/latest/mgmt/data-api.html).
