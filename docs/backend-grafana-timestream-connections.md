# Managed Grafana Timestream connections

Managed Grafana → Timestream (`queries`) reuses `TimestreamTableAccessConfig` and requires an existing `table_name`. The editor discovers this selector through `/api/connection-schemas`. The Timestream node provisions a LiveAnalytics database; tables and ingestion remain separately managed. Connect each table required by a query, including every table in a join. Repeated identical bindings aggregate deterministically, while multiple tables in one database remain independent bindings.

`GrafanaTimestreamSource` contributes to the same workspace-owned customer-managed role used by [Prometheus](backend-grafana-prometheus-connections.md) and [CloudWatch Logs](backend-grafana-cloudwatch-connections.md). Each database exports its native ARN, name, and ARN-derived Region. A typed `timestream_tables` input map carries those values plus the selected table name into Grafana. Terraform guards validate database ARN/name/Region consistency, matching account/partition, and explicit table names without IAM wildcards. Same-account cross-Region queries are supported; organization role chaining and cross-account data-source roles remain unmodeled. Target outputs contain no Grafana role dependencies.

The shared policy grants `timestream:Select`, `timestream:DescribeTable`, and `timestream:ListMeasures` on exact selected table ARNs. `timestream:DescribeDatabase` and `timestream:ListTables` use connected database ARNs. This permits table-name discovery inside a connected database without granting reads on its other tables. The connection grants no record writes, unloads, scheduled-query administration, or table/database creation. See the [Timestream authorization reference](https://docs.aws.amazon.com/service-authorization/latest/reference/list_timestream.html).

`timestream:DescribeEndpoints`, `timestream:ListDatabases`, `timestream:SelectValues`, and `timestream:CancelQuery` require wildcard resources. An `aws:RequestedRegion` condition restricts them to connected database Regions. Regional discovery can reveal other database names, and cancellation can affect other running queries in those Regions. `SelectValues` permits table-independent queries such as the plugin's `SELECT 1` health check; it does not grant reads on unrelated tables. Preview describes these limits. See the [plugin's health and query implementation](https://github.com/grafana/timestream-datasource/blob/main/pkg/timestream/datasource.go) and [AWS SELECT policy examples](https://docs.aws.amazon.com/timestream/latest/developerguide/security_iam_id-based-policy-examples.html).

The Grafana module exports `timestream_data_sources`, keyed by `<database-node-name>:<table-name>`. Each Grafana API payload uses `grafana-timestream-datasource`, proxy access, default AWS role credentials, the native Region, and default database/table settings. Display names longer than Grafana's 190-character limit are shortened with a binding-specific hash suffix; selectors and output keys retain their full names. The database and table defaults contain quoted SQL identifiers, matching the plugin's selector values and supporting dots, hyphens, and reserved words in names. UIDs derive from the native table ARN, so changing a diagram node name preserves the underlying data-source UID. No endpoint URL is guessed: the SDK discovers the regional Timestream query endpoint. No access keys, passwords, or Grafana tokens are exported. See [plugin configuration](https://grafana.com/docs/plugins/grafana-timestream-datasource/latest/configure/), [macro implementation](https://github.com/grafana/timestream-datasource/blob/main/pkg/timestream/macros.go), and [Grafana's data-source schema](https://github.com/grafana/grafana/blob/main/pkg/services/sqlstore/migrations/datasource_mig.go).

Install a Timestream plugin compatible with the workspace's Grafana version, then apply each exported payload through Grafana's data-source API or UI with an authorized Grafana identity. Current plugin releases require Grafana 10.4 or later; refer to the [plugin requirements](https://grafana.com/docs/plugins/grafana-timestream-datasource/latest/). For a workspace named `grafana` connected to a database node named `telemetry` and table `cpu-load`, extract the settings from the generated environment directory:

```sh
terraform output -json grafana > grafana-outputs.json
jq '.timestream_data_sources["telemetry:cpu-load"]' grafana-outputs.json > timestream-data-source.json
```

Submit that JSON to `POST https://<workspace_endpoint>/api/datasources`, or use `PUT /api/datasources/uid/<uid>` for updates. Use Save & test to check credentials and endpoint discovery, then run a query against the selected table to verify data access. The generator does not manage Grafana object lifecycle, ingest records, or provision tables. User access, dashboards, network connectivity, and external encryption-key permissions remain separately configured.

The existing database generator uses Timestream's default managed encryption and exposes no customer-managed key setting. This connection adds no KMS grants; any externally changed encryption policy needs separate permissions. LiveAnalytics is closed to new customers as of June 20, 2025, so this integration requires an eligible existing account. It does not target Timestream for InfluxDB. See [AWS database encryption defaults](https://docs.aws.amazon.com/timestream/latest/APIReference/API_CreateDatabase.html) and [AWS's availability notice](https://docs.aws.amazon.com/timestream/latest/developerguide/doc-history.html).
