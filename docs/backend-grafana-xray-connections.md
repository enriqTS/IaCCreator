# Managed Grafana X-Ray connections

Managed Grafana → X-Ray (`queries`) uses the typed empty connection configuration. Connect the X-Ray group nodes whose native filters and Regions should be available in Grafana. Connected group names use a conservative subset of 1–32 ASCII letters, digits, underscores, or hyphens; the reserved name `Default` is rejected. A group must have a nonempty filter expression. Filter syntax remains an AWS concern; the generator does not parse or rewrite it. See [X-Ray group creation](https://docs.aws.amazon.com/xray/latest/api/API_CreateGroup.html).

`GrafanaXRaySource` contributes to the workspace-owned customer-managed role shared with Prometheus, CloudWatch Logs, Timestream, OpenSearch, Athena, and Redshift. The X-Ray module exports native group ARN/name, ARN-derived Region, filter expression, and Insights setting through a typed `xray_groups` input. Terraform preconditions verify concrete ARN shape, account/partition agreement, matching names/Regions, and nonempty filters, including overrides after generation. Same-account cross-Region groups are supported; organization and cross-account role chaining are excluded. Target outputs depend only on the native group, avoiding reverse dependencies on Grafana. No editable service fields or standalone group behavior change.

Trace reads grant `xray:BatchGetTraces`, `GetTraceSummaries`, `GetTraceGraph`, `GetGroups`, `GetTimeSeriesServiceStatistics`, and `GetServiceGraph` on wildcard resources, restricted by `aws:RequestedRegion` to connected Regions. These APIs do not support group-resource authorization. The role can read unrelated traces, metadata, graphs, and groups in those Regions; query filters are defaults rather than IAM boundaries. The connection grants no trace ingestion, group mutation, sampling configuration, or encryption administration. See the [X-Ray authorization reference](https://docs.aws.amazon.com/service-authorization/latest/reference/list_xray.html).

`GetInsightSummaries` and `GetInsight` are added only for Regions containing a connected native group with Insights enabled. These permissions also cover unrelated insights in those Regions. Group Insights configuration remains user-controlled. `ec2:DescribeRegions` supports discovery in older plugin versions and uses the same request-Region restriction; returned Region names can include Regions outside the allowed X-Ray query scope. Existing identity grants may broaden access, while other service policies can deny it. Per-Grafana-user isolation is not supplied by the shared role.

The workspace exports `xray_data_sources`, keyed by native Region. Each payload uses `grafana-x-ray-datasource`, proxy access, default AWS role credentials, and the native Region. Its UID hashes partition/account/Region, so adding or removing groups and renaming diagram nodes preserves the regional data-source identity. Passwords, access keys, tokens, custom endpoints, and assume-role settings are not exported. Install a plugin compatible with the workspace's Grafana version; newer plugin versions may display the name AWS Application Signals while keeping this plugin ID. See [Managed Grafana X-Ray setup](https://docs.aws.amazon.com/grafana/latest/userguide/x-ray-data-source.html) and [plugin configuration](https://grafana.com/docs/plugins/grafana-x-ray-datasource/latest/configure/).

Group selection belongs to queries rather than data-source configuration. `xray_query_defaults`, keyed by group node name, exports the regional `datasource_uid` and individual query targets under `queries`: `trace_summaries` uses the native filter, while `service_map` uses the native `GroupARN`, `GroupName`, and `FilterExpression` object. Insights-enabled groups also export an `insights` target with state `All`. Targets select X-Ray query mode, native Region, and the plugin's query types. They are individual defaults, not complete dashboards or `/api/ds/query` requests; attach the data source, assign distinct `refId` values when combining targets, and select a time range. See the plugin's [query types](https://github.com/grafana/x-ray-datasource/blob/main/src/types.ts), [trace summaries](https://github.com/grafana/x-ray-datasource/blob/main/pkg/datasource/getTraceSummaries.go), and [service-map implementation](https://github.com/grafana/x-ray-datasource/blob/main/pkg/datasource/getServiceMap.go).

For workspace `grafana`, group node `traces`, and Region `us-east-1`, run from the generated environment directory:

```sh
terraform output -json grafana > grafana-outputs.json
jq '.xray_data_sources["us-east-1"]' grafana-outputs.json > xray-data-source.json
jq '.xray_query_defaults.traces' grafana-outputs.json > xray-query-defaults.json
```

Apply the data-source payload to `POST https://<workspace_endpoint>/api/datasources`, or update with `PUT /api/datasources/uid/<uid>`, using an authorized Grafana identity. Save & test checks group discovery. Configure an Explore or dashboard query using one of the exported targets and query an interval containing ingested traces. See the plugin's [health check](https://github.com/grafana/x-ray-datasource/blob/main/pkg/datasource/CheckHealth.go).

Application instrumentation, trace ingestion, sampling, dashboards, Grafana user access, encryption grants, and AWS API network reachability remain separately configured. Use X-Ray query mode; Application Signals service/SLO queries, OAM cross-account observability, and CloudWatch Transaction Search APIs need separate integrations and receive no grants here.
