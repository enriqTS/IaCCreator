# SQS dead-letter connections

Connect a source SQS queue to another SQS queue with `dead_letters_to`. `max_receive_count` defaults to 5 and accepts integers from 1 through 1,000. The editor receives that field and its bounds from the backend connection schema. See [SQS maximum receives](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/sqs-configure-dead-letter-queue.html).

Each source has one destination and receive count. Duplicate identical connections are idempotent; conflicting settings, self-links, and cycles are rejected. Standard queues require standard destinations, and FIFO queues require FIFO destinations. One destination can accept up to ten distinct sources through a single `byQueue` redrive allow policy. The generator owns that complete allow list, so unmanaged sources must not share its policy. See [SQS redrive attributes](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/APIReference/API_SetQueueAttributes.html).

The destination module owns both its standalone allow policy and the standalone redrive-policy attachments for its connected sources. Source queue ARNs, URLs, and FIFO flags travel through native outputs and typed inputs. No queue module depends back on its destination; acyclic chains and shared destinations therefore avoid reciprocal module dependencies. Redrive attachments depend on the allow policy. Terraform preconditions enforce matching FIFO flags and the same account, partition, and region after variable overrides. The registry also restricts this connection to one region.

These are separate [redrive-policy](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/sqs_queue_redrive_policy) and [redrive-allow-policy](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/sqs_queue_redrive_allow_policy) resources; no general queue access policy or IAM execution role is created. Do not manage the same redrive attributes outside this generated project.

Choose a destination retention period longer than the source's, and configure application retries and visibility timeouts separately. FIFO dead-lettering can disrupt end-to-end ordering. Alarms, manual replay, and consumer access remain separate. Consumers of encrypted dead-letter messages can need decrypt permission on original source keys as well as the destination key. See [dead-letter queue behavior](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/sqs-dead-letter-queues.html) and [consumer key requirements](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/sqs-key-management.html).

Tests validate generated Terraform and dependency graphs for both queue types with single, shared, and chained destinations. No live message delivery or replay is tested.
