# Managed Grafana OpenSearch connections

Managed Grafana → OpenSearch (`queries`) requires an existing concrete `index_name` and accepts `time_field`, defaulting to `@timestamp`. `GrafanaOpenSearchConfig` exposes both fields through `/api/connection-schemas`. The index selects Grafana's default; query permission covers the connected domain. Provision indexes, date mappings, and ingestion separately. Duplicate bindings aggregate deterministically; conflicting time fields for the same workspace/domain/index are rejected.

`GrafanaOpenSearchSource` contributes native metadata and permissions to the workspace-owned customer-managed role shared with [Prometheus](backend-grafana-prometheus-connections.md), [CloudWatch Logs](backend-grafana-cloudwatch-connections.md), and [Timestream](backend-grafana-timestream-connections.md). Each domain exports its native name, engine version, explicit-index setting, and ARN-derived Region alongside the existing ARN and endpoint outputs. A typed `opensearch_sources` map carries these identities and connection defaults into Grafana. Target outputs reference native domain resources and contain no workspace dependencies. Same-account cross-Region queries are supported; cross-account role chaining is unmodeled.

The policy grants GET on the domain root for version discovery and on configured indexes' `/_mapping`, `/_mapping/*`, `/_field_caps`, and `/_settings/index.number_of_shards` paths. POST is granted only on each connected domain's root `/_msearch` path. Root index discovery, cluster administration, SQL, PPL, document mutation, and configuration APIs receive no grants. See the [plugin's client requests](https://github.com/grafana/opensearch-datasource/blob/main/pkg/opensearch/client/client.go) and [health/resource requests](https://github.com/grafana/opensearch-datasource/blob/main/pkg/opensearch/opensearch.go).

Root multi-search accepts index names inside request bodies. Its IAM URL permission permits queries against any index in that domain; the configured default is not an IAM index boundary. Domain policies and fine-grained security role mappings remain externally managed and may broaden or deny access. Use fine-grained authorization if indexes need distinct access boundaries. See [AWS access-control guidance](https://docs.aws.amazon.com/opensearch-service/latest/developerguide/ac.html).

Connected domains enforce HTTPS with TLS 1.2 or newer and explicitly enable `rest.action.multi.allow_explicit_index`. The repository's [Lambda/ECS index clients](backend-opensearch-connections.md) and [AppSync OpenSearch resolvers](backend-appsync-opensearch-connections.md) disable that same domain-wide option to preserve their URL-based restrictions. Connecting either kind of client to a Grafana-connected domain is rejected regardless of edge order. Use separate domains for those generated integrations. Unconnected domains retain their existing configuration.

Terraform preconditions validate concrete index/time-field syntax, native domain ARNs, matching account/partition, endpoint/name/Region consistency, supported engine-version syntax, and enabled explicit indexes. The connection uses the provider's standard `endpoint` hostname, including public `search-` and private `vpc-` endpoints; custom endpoints, Serverless collections, and dual-stack `endpoint_v2` are unmodeled. Network access remains external. In particular, this connection does not configure Managed Grafana VPC connectivity. See the [provider resource reference](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/opensearch_domain).

The Grafana module exports `opensearch_data_sources`, keyed by `<domain-node-name>:<default-index>`. Each API payload uses `grafana-opensearch-datasource`, proxy access, the native HTTPS endpoint, and SigV4 with default workspace-role credentials and the native domain Region. OpenSearch and legacy Elasticsearch flavors derive from the native engine version; two-part versions gain a zero patch component. Defaults include the selected index, time field, and a `10s` minimum interval; PPL and Serverless modes are disabled. UIDs derive from the native domain ARN and index, preserving identity across diagram node renames. Display names longer than 190 characters receive a hash suffix; selectors and output keys retain their full values. No passwords, keys, or Grafana tokens are exported. See [plugin configuration](https://grafana.com/docs/plugins/grafana-opensearch-datasource/latest/configure/).

Install an OpenSearch plugin compatible with the workspace's Grafana version, then apply the payload through the Grafana API or UI using an authorized identity. For a workspace named `grafana`, domain node `search`, and index `application-records`, extract the settings from the generated environment directory:

```sh
terraform output -json grafana > grafana-outputs.json
jq '.opensearch_data_sources["search:application-records"]' grafana-outputs.json > opensearch-data-source.json
```

Submit the JSON to `POST https://<workspace_endpoint>/api/datasources`, or use `PUT /api/datasources/uid/<uid>` for updates. Use Save & test to check index mappings and the date field, then run a query to verify access. Reapply settings after engine upgrades so the plugin's configured version matches the domain. Grafana objects, user access, dashboards, fine-grained role mappings, and ingestion are separately managed.
